## UI を作る・直すとき(このサイトのすべての HTML)
- 部品は [ui-kit.html](../ui-kit.html)(パーツ台帳)にあるものを使う。見た目は [ui/kit.css](../ui/kit.css)。部品の詳しい決まりは [htmlParts.md](htmlParts.md)
- ユーザーは**テーマ名**(そら=水色 / いちご=ピンク / みかん=オレンジ / レモン=黄色(remon) / もり=緑(mori) / ぶどう=むらさき(budo))、**部品の名前**(「箱」「ぷっくりボタン」「リンクカード」など)、**色の名前**(「アクセント」「付箋・ミント」など)で指示する
- 新しいページは `<html data-theme="…">` + `ui/kit.css` を読み込んで作る。色は直接書かず `var(--accent)` などを使う
- テーマの目安:サイトのトップ=そら、キャラ紹介・関係辞典=いちご、ツール=みかん(なんちゃってレイドシュミレーターだけ ぶどう)
- どのページも `ui/scrollbar.css` を読み込む(`<link rel="icon">` のすぐ下)。スクロールバーの形はキャラカと同じ、色はその場所の色(近くの `--c` → `--primary` → `--accent` をうすく)。場所ごとに変えるときは入れ物に `--us-thumb` などを書く(Tシャツのページはまだ付けない)
- 今あるページ(index / coupling / profile / キャラカ / Tシャツ)は、まだ ui/kit.css を使っていない(それぞれのページの中に CSS がある)。kit.css を後から読み込むと、ページ全体の見た目まで変わるので注意(必要な部品の CSS だけ、ページの中に写す)
- 合言葉は「かわいく」:パステル・太めの枠線・まるい角・押すと沈むボタン・丸ゴシック(M PLUS Rounded 1c)
- スマホ(幅 320px)でも崩れないこと。入力欄の文字は 16px 以上(PC の見た目を変えたくないときは、`@media (max-width: 999.98px)` の中だけ 16px にしてよい)
- **外側の余白を多くしない(ユーザーの好み)**:PC(広い画面)では、画面の左右を大きく空けて真ん中に小さくまとめない。特に一覧・キャラ選択・ギャラリーなど「並べて見せる」部分は、画面の幅いっぱい近くまで使う(内容に max-width を付けるなら大きめに。文章を読ませる部分だけは、読みやすい幅にしてよい)。スマホ(狭い画面)は余白多めでもよい
- **説明の文章は、なるべく画面に出さない**(ユーザーの好み。「使い方」の箱や長い注意書きは邪魔、とのこと)。どうしても必要なら1行で
- どのページにも、ブラウザのタブのアイコンを付ける:`<title>` のすぐ下に `<link rel="icon" type="image/png" href="Icon.png">`(フォルダーの深さに合わせて `../Icon.png` など)。`Icon.png` は青い傘(256×256)
- どのページにも「あめちゃんもの置き」(トップへ戻る文字だけのリンク。「あめちゃん/もの置き」の小さめの2行)を付ける:`ui/site-header.js` を `defer` で読み込み、上の帯があればその帯に `data-site-bar` を付ける(なければ左上に浮く)。ページ一覧は付けない
  - 行き来は関係のあるページ同士だけ(パーツ台帳 ⇔ パーツメーカー、キャラカ ⇔ 枠エディタ・シンボルエディタ。SVGメーカーはトップのカードから開くだけ)。Tシャツのページにはまだ付けない
- 新しい部品を作ったら、名前を決めて ui/kit.css と パーツ台帳の両方に足す(書き方は [htmlParts.md](htmlParts.md))

## コード規約(HTML / CSS / JS)
- 見た目:字下げ2スペース、文字列は `"`、セミコロンを付ける、`const` / `let`(`var` は使わない)、`async` / `await`、イベントは `addEventListener`、ドラッグは pointer イベント
- 名前:JS は camelCase、定数は大文字(`MAX_GRID`)、CSS のクラスは kebab-case、id は camelCase。ローマ字は使わない
- 状態のクラスは3つだけ:選んでいる=`.on`、開いている=`.open`、使えない=`.is-disabled`
- 同じ処理を作り直さない・コピーして写さない:みんなで使う物は `ui/`、キャラカ系は `characa/frames.js` に置いて読み込む(無ければそこに足す)。`$`・エスケープ・`toast`・ぐるぐる・色コードの読み取りは `ui/util.js`([htmlParts.md](htmlParts.md))
- 画面の幅の切り替え点は 1000px(広い・狭い)・400px・360px を基本にする
- コメントは日本語で、分かりにくい所にだけ書く
- 今あるコードは一気に直さない。そのファイルを次に触るときに合わせる
- Hook(`.claude/settings.json` → `.claude/hooks/code-style.js`)が、AI が .html / .js / .css に**新しく書く行**を見て、`var`・`onclick=` / `el.onclick =`・mouse / touch イベント・`.selected` などの状態クラス・決まり以外の `@media` の幅・タブの字下げ があれば書き換えを止める(長押しドラッグ中にスクロールを止める `touchmove`(`passive: false`)は通す)。止められたら規約に合わせて書き直す

## 作業の決まり(AI 向け)
- **ユーザーが /ok を打つまで、作業(ファイルの書き換え)を進めない**。何をどう直すかを確認の形で出して、返事を待つ(調べる・測るだけなら先にしてよい)。言葉で「いいよ」と言われたときも、/ok を打ってもらう
- 確認したいことは、ユーザーがはっきり「はい」と言うまで進めない(/ok が打たれても、答えがなければ促す)。「返事がなければおすすめで進めます」という聞き方は絶対にしない。「おまかせ」「どっちでもいい」と言われても、こちらで決めず、ユーザーに決めてもらう
- **提案に、おすすめや既定の選択肢を付けない。**
  - 「おすすめ」「返答がない場合は○○で進めます」「どちらでもよい」は禁止。
  - 選択肢は並べるだけにし、ユーザーが判断してから進める。
  - 判断を依頼するときは、質問に番号(1, 2…)、選択肢に記号(A, B…)を付ける。ユーザーは `/ok 1B 2A` のように、番号と記号の組で答えられるようにする。
  - 答えていない質問が残っていたら、作業せず、残りの回答を求める。
- **了承と作業の終わりの確認**(`.claude/skills/ok/`・`.claude/hooks/task.js`・`.claude/settings.json`)
  - /ok が打たれると、Hook が「作業中」の目印を作り、そのときのファイルの状態を覚える。目印は**スレッド(セッション)ごと**(`.claude/state/task-<セッションID>.json`。コミットしない)なので、別のスレッドが終わっても、自分の目印は消えない。目印が無いと、このフォルダーのファイルは Edit / Write で書き換えられない(Hook が止める)。node などのスクリプトで書き換えるときも、同じく /ok のあとだけにする
  - **ロック**:Edit / Write で書き換えたファイルは、そのスレッドが `done` するまでロックされ、ほかのスレッドは書き換えられない(Hook が止める)。止められたら、ユーザーに伝えて待つ(`wait`)か、別のファイルで作業する
    - `docs/Backlog.md` はロックしない(どのスレッドも最後に書き足すため。Edit は読んだあとで中身が変わっていたらエラーになるので、上書きはされない)
    - 最後に書き換えてから3時間たったスレッドのロックは無視する(閉じたスレッドの残り)。すぐ外すときは、ユーザーが `/ok unlock` を打つ(ほかのスレッドのロックが全部外れる)
    - スクリプト(`sed -i`・node など)での書き換えはロックされない。ほかのスレッドが動いているときは Edit / Write で書き換える
    - `done` の確かめでは、ほかのスレッドだけが書き換えたファイルは数えない
  - 作業が終わったら /ok のスキルの手順どおり、見つけた・後回しにしたことを Backlog.md と md に足し、`node .claude/hooks/task.js done --review "…"` で確かめる。作業中に変えたファイルについて「コードを変えたのにそのページの md が変わっていない」「次の候補・進捗が変わったのに Backlog.md が変わっていない(逆も)」「最終更新が今日でない」を見る。通ると目印が消える
  - /ok のあとでユーザーが作業を止めた(中断した)ら、次にユーザーが文を送ったとき、Hook が会話の記録を見て目印とロックを消す(書き換えたファイルはそのまま。`done` の確かめもしない)。止めたあとすぐ /ok なら、そのまま続く
  - 未調査:`done` をしていないのに目印が消えていたことがある(ツールの実行を止めたとき)
  - 目印が残ったまま終わろうとすると、Hook が1回だけ止める。質問して返事を待つときは `node .claude/hooks/task.js wait` を実行してから終える
  - ページを増やしたら、`task.js` の `DOC_MAP`(コードのファイル → md)にも1行足す
- **返事・説明は日本語**。専門用語はなるべく使わず、手順はメニュー名を具体的に書く
- **コミット・プッシュはしない、すすめない**(ユーザーが必ず自分でやる)。報告では、変えたファイルを書く
- ユーザーは合言葉・好みがはっきりしている。言われていない機能・説明文を勝手に足さない。迷ったら短く聞く
- **画面の確認**
  - ブラウザのペイン(preview_start / navigate)は自分から開かない。開くと空タブが残って、ユーザーが困る
  - Write ツールで `.html` を作る・書き換えると、アプリが自動でそのファイルのタブを開く。HTML は node のスクリプトで書くか、Write のあとでタブを確認して全部閉じる
  - 確認は見えないブラウザで:`C:/Program Files/Google/Chrome/Application/chrome.exe` を `--headless=new --remote-debugging-port=… --user-data-dir=一時フォルダー` で立て、Node の WebSocket(CDP)で動かす。写真も撮れる。拡大率のずれは deviceScaleFactor で再現
  - 確認用のサーバーは、自分で Node の小さなサーバーをポート **8765** に立てて、そのプロセスだけを止める。**ポート 8000 はユーザーが `npx http-server C:/Users/kikuchi/Documents/AmechanCreate -p 8000 -c-1` で使う**ので、さわらない
  - このPCの `python` は動かない(Microsoft Store の案内だけ)
- **ファイルの書き換え**
  - 手元の改行はファイルでちがう(CRLF:`index.html`・`tshirt-designer.html`・`dot-maker.html`・`characa/` の app.js・frames.js・style.css・worker.js・job-icons.js・templates の .json、`docs/dotMaker.md`。`coupling.html` は CRLF と LF がまざる。ほかは LF)。今の状態は `git ls-files --eol` の `w/…` で見る。node のスクリプトで、いったん LF にして直し、元の改行に戻す。`sed -i` は使わない(CRLF が消える)
  - bash のヒアドキュメントの中に JS の正規表現(`\/` など)を書くと、`\` が消えることがある。正規表現を含むスクリプトは Write ツールで書く(String.raw を使う)
- 新しい決まり・仕様が決まったら、合う md に書き足す([CLAUDE.md](../CLAUDE.md) は目次だけにする)
- **トップ(index.html)から行けるページ(カード・ボタン)を増やしたら、必ずそのページの md を作る**。別のスレッドに移っても、その md を読めばすぐ作業を続けられるように書く:何をするものか・ファイルと役目・画面・しくみ(コードのどこで何をしているか)・確認のしかた・今の進捗(できたこと)・次の候補・作業のメモ。見本は [dotMaker.md](dotMaker.md)。作ったら、この md のページ一覧、分野の基盤(例:[Tools.md](Tools.md) のツール一覧)、[CLAUDE.md](../CLAUDE.md) の目次に1行ずつ足す
- md でコードの場所を書くときは、**関数名・変数名で書く。行番号は書かない**(コードを直すたびにずれて、md と合わなくなる)
- 個別の md の「作業のメモ(AI 向け)」には、そのページだけのことを書く。この md にあることはくり返さない(無ければ省く)
- **やること(未対応・候補)が増えた・片付いたら、[Backlog.md](Backlog.md) にも1行で足す・消す**(くわしくは各 md)
- **ユーザー確認系は、どの md にも書かない**(ユーザーの好み):ユーザーが画面・実機で確かめること(「未確認」)と、ユーザーがやる作業(データを入れる・デプロイ・コミットなど)。必要なら報告の中で伝えるだけにする
- **ページ・仕組みを変えたら、同じ作業の中で、変えた所に当たる md も直す**(画面・しくみ・進捗など、変わった所を書き換え、「最終更新」の日付も変える)。md と中身がずれたままにしない
- **md は端的に書く**。作業の前に読む md(目次・基盤・個別の md)を合わせても、コンテキストの 15% を超えないようにする。同じことを何度も書かない・長い説明や例は削る・古くなった記録は短くまとめるか消す
