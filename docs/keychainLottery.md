## 画面(上から順に1つずつ出す)
1. 「景品」= 在庫がある種類ごとに `.prize`(四角い下地。うすいむらさき・角なし。中の上に画像 `.prize-img`、下に名前のボタン `.ub-prize`。ボタンはパーツメーカーで作った形:枠線なし・ぷっくり影・浮く・沈む。角は 14px。色は白。押しても何も起きない。並べるのは `.tiles`。数は出さない。画像が無ければボタンだけ)。当たりの画像も同じ四角い下地+ 引換コードの欄(1つの欄に1つ。「+」で欄を足す。欄が2つ以上のときだけ右に ✕)+ 引くボタン(欄が1つなら「引く」、2つ以上なら「まとめて引く」。全部まとめて引く。1つずつ引くのは、ユーザーの希望でなくした)
2. 玉が揺れる(`SHAKE_MS` = 1.4 秒)→「当たり」とコードごとの画像・種類・コード → 「前回使用した住所を使用」(前に送ったことがあるときだけ)・氏名・住所の欄と「送る」(全部まとめて送る)
3. 「受け付けました」とコードごとの当たり(画像つき)。コードの欄は1つに戻す

## しくみ
- 画像:「景品」の C 列(ドライブの共有リンク → サムネイルの URL `toImageUrl`。ほかの URL はそのまま)を先に使い、無ければ `IMAGE_FOLDER_ID` のフォルダの「種類の名前.png」など(`readFolderImageIds`。拡張子なしでも合う)。大きさは `IMAGE_SIZE`。`doGet` が `{ items: [{ name, img }] }` で返し、ページは `images`(名前 → URL)に覚えて当たりにも使う。キャラクター紹介の `profile_api.gs` と同じ形
- スプレッドシートのシート:「景品」(種類・在庫数・画像)・「コード」(引換コード)・「応募」(最後に送った日時・氏名・住所・コード・当たり)。無いシートは `withLock` が見出しつきで作る
- 「応募」は1人1行。氏名と住所が両方同じなら同じ人として、コードと当たりを「、」でつないで足す(`SEP`。空白のちがいは `cleanText` でそろえる)。住所がちがえば別の行
- 1つのコードで1個。コードは前後の空白を消し、大文字にして比べる(`normCode`)。「応募」のコードの列にあれば使用済み(`usedCodes`)。ないコード・使用済みのコードは `checkCodes` が `codes` に入れて返し、ページはエラーの後ろに出す
- 引く(`draw`):`codes`(入れた全部)と `draw`(今引くもの)を受け取る。在庫数で重みを付けて選ぶ。**在庫は減らさず、シートにも書かない**。当たりはスクリプトのプロパティ `draw:コード` に覚える(ページで書きかえられないように)。いっしょに入れたほかのコードの当たりは在庫から引いて考える(在庫より多く当たらない。ページは今 `draw` に全部を入れて送る)。送る前なら何回でも引き直せる(タブを閉じたら何も起きない。ユーザーの希望)
- 送る(`send`):全部の当たりの在庫が足りるか先に見て、足りなければ `gone`(何も書かない。プロパティを消す。ページは引く画面に戻し、景品を読み直す)。足りれば在庫を減らし「応募」に書く。先頭に `'` を付けて式・数にしない(読むときは `stripQuote`)。プロパティが無ければ `nodraw`
- 同時に送っても在庫がずれないように、`LockService` で1人ずつ処理する
- 住所・氏名はページから読めない(返すのは種類の名前だけ)。送れたら、そのブラウザの localStorage `keychain-lottery:address`(`SAVE_KEY`)に氏名・住所を覚える(「前回使用した住所を使用」のため。ユーザーの希望)
- ページ:`API_URL`・`api`(POST は text/plain の JSON。Google の CORS を通すため)・`ERRORS`・`loadItems`・`addCodeRow`・`renderCodeRows`(✕ とボタンの文字)・`readCodes`(空の欄・同じコードは除く)・`draw`・`send`・`loadSaved`・`imgHtml`・`hitHtml`・`show`(画面の切りかえ)。状態は `codes`・`hits`・`images`
