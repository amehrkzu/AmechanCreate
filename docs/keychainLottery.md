# アクキーくじ(keychain-lottery.html)

最終更新:2026-11-05

- フレンドにアクリルキーホルダーをくじで配るページ(2026-11-05 に作った)。引換コードを入れて引き、当たったら氏名・住所を送る。同じ人が何回でも回せる(コードを何個も配る)
- ページ `keychain-lottery.html` + Apps Script `keychain-lottery_api.gs`(Googleスプレッドシートに書く。しくみはプロフィールの `profile_api.gs` と同じ)。デプロイ済み(`API_URL` に入っている)
- テーマは **ぶどう**(ユーザーの希望)。`ui/kit.css`・`ui/util.js`・`ui/site-header.js`・`ui/scrollbar.css`
- トップにカードは出さない(URL を知っている人だけ。ユーザーの希望)

## 画面(上から順に1つずつ出す)
1. 「景品」= 在庫がある種類ごとに `.prize`(四角い下地。うすいむらさき・角なし。中の上に画像 `.prize-img`、下に名前のボタン `.ub-prize`。ボタンはパーツメーカーで作った形:枠線なし・ぷっくり影・浮く・沈む。角は 14px。色は白。押しても何も起きない。並べるのは `.tiles`。数は出さない。画像が無ければボタンだけ)。当たりの画像も同じ四角い下地+ 引換コードの欄(1つの欄に1つ。「+」で欄を足す。欄が2つ以上のときだけ右に ✕)+ 引くボタン(欄が1つなら「引く」、2つ以上なら「まとめて引く」。全部まとめて引く。1つずつ引くのは、ユーザーの希望でなくした)
2. 玉が揺れる(`SHAKE_MS` = 1.4 秒。揺れている間は「当たり」の文字 `#hitLabel` も出さない)→「当たり」とコードごとの画像・種類・コード → 「前回使用した住所を使用」(前に送ったことがあるときだけ)・氏名・郵便番号・都道府県・市区町村と町名・番地・建物名と部屋番号の欄(建物名だけ空でもよい)と「送る」(全部まとめて送る)
3. 「受け付けました」と、このブラウザで今までに送った当たり全部(今回の分も。画像つき。`loadHistory`・`addHistory`、localStorage `keychain-lottery:history` = `HISTORY_KEY`。別の端末・ブラウザの分は出ない。gs を変えないためにこの形にした)。コードの欄は1つに戻す。「続けて引く」(`#againBtn`)で引く画面に戻り、景品を読み直す
- キーで動くものは作らない(コードの欄・郵便番号の欄の Enter では何も起きない。ユーザーの希望)

## しくみ
- 画像:「景品」の C 列(ドライブの共有リンク → サムネイルの URL `toImageUrl`。ほかの URL はそのまま)を先に使い、無ければ `IMAGE_FOLDER_ID` のフォルダの「種類の名前.png」など(`readFolderImageIds`。拡張子なしでも合う)。大きさは `IMAGE_SIZE`。`doGet` が `{ items: [{ name, img }] }` で返し、ページは `images`(名前 → URL)に覚えて当たりにも使う。ドライブのサムネイルは透けた部分が黒くなる(らしい)ので、ページの `fullImage` が `drive.google.com/thumbnail?id=ID` を元の画像 `lh3.googleusercontent.com/d/ID=s0` に書きかえて出す(gs は変えない。重くなる。ユーザーが選んだ)。キャラクター紹介の `profile_api.gs` と同じ形
- レア:「景品」の D 列が「○」(〇・◯ も可)ならレア(`readPrizes` の `rare`)。`doGet` が `rare` も返し、ページは `rares`(名前 → レアか)に覚える。景品の一覧・当たり・「受け付けました」で、画像そのものの右上の角(`imgHtml` が画像と札を `.pic` に入れる。画像が無ければ `.prize`・`.hits li` の右上)に、少し傾けた金ぴかの「レア！」(`.rare-badge`・`RARE_HTML`。金色はキットに無いのでページで `--gold` などを決める)。札は、ばねをはじいたように揺れて止まる → 少し休む、をくり返す(`rareSpring`。2.4 秒)。送った記録(`HISTORY_KEY`)にも `rare` を残す
- スプレッドシートのシート:「景品」(種類・在庫数・画像・レア)・「コード」(引換コード)・「応募」(最後に送った日時・氏名・住所・コード・当たり)。無いシートは `withLock` が見出しつきで作る
- 「応募」は1人1行。氏名と住所が両方同じなら同じ人として、コードと当たりを「、」でつないで足す(`SEP`。空白のちがいは `cleanText` でそろえる)。住所がちがえば別の行
- 1つのコードで1個。コードは前後の空白を消し、大文字にして比べる(`normCode`)。「応募」のコードの列にあれば使用済み(`usedCodes`)。ないコード・使用済みのコードは `checkCodes` が `codes` に入れて返し、ページはエラーの後ろに出す
- 引く(`draw`):`codes`(入れた全部)と `draw`(今引くもの)を受け取る。在庫数で重みを付けて選ぶ。**在庫は減らさず、シートにも書かない**。当たりはスクリプトのプロパティ `draw:コード` に覚える(ページで書きかえられないように)。いっしょに入れたほかのコードの当たりは在庫から引いて考える(在庫より多く当たらない。ページは今 `draw` に全部を入れて送る)。**一度引いたコードの当たりは固定**(`fixed`。もう一度引いても、タブを閉じても同じ。リセマラ対策。ユーザーの希望)。新しく引くのは、まだ当たりの無いコードだけ(`fresh`)
- 送る(`send`):全部の当たりの在庫が足りるか先に見て、足りなければ `gone`(何も書かない。足りなかったコード `short` だけプロパティを消して `codes` で返す。そのコードだけ引き直せる。ページは引く画面に戻し、景品を読み直す。同時に同じ種類を引いた人たちの、あとの人がこうなる)。足りれば在庫を減らし「応募」に書く。先頭に `'` を付けて式・数にしない(読むときは `stripQuote`)。プロパティが無ければ `nodraw`
- 同時に送っても在庫がずれないように、`LockService` で1人ずつ処理する
- 住所・氏名はページから読めない(返すのは種類の名前だけ)。送れたら、そのブラウザの localStorage `keychain-lottery:address`(`SAVE_KEY`)に欄ごとの値(`FORM_IDS`)を覚える(「前回使用した住所を使用」のため。ユーザーの希望)
- 郵便番号:欄の右の「住所検索」(`#zipBtn`)を押したときだけ(欄の Enter では調べない)、`lookupZip` が zipcloud(`ZIP_API`。郵便番号だけ送る)で調べ、都道府県・市区町村と町名を入れて番地の欄へ移る(入れただけで勝手に変わるのはいや、とユーザー)。全角の数字も読む(`zipDigits`)。7けたでない・見つからないときは `#zipMsg`(`zipMsg`)に出す
- 住所の欄は分けているが、gs には1つの文字にまとめて送る(`〒123-4567 都道府県市区町村番地 建物名`)。gs と「応募」の列は変えていない(デプロイを減らすため)
- ページ:`API_URL`・`api`(POST は text/plain の JSON。Google の CORS を通すため)・`ERRORS`・`loadItems`・`addCodeRow`・`renderCodeRows`(✕ とボタンの文字)・`readCodes`(空の欄・同じコードは除く)・`draw`・`send`・`readForm`・`lookupZip`・`loadSaved`・`imgHtml`・`hitHtml`・`show`(画面の切りかえ)。状態は `codes`・`hits`・`images`
